I built an SSH app for my phone with AI, and Thai typing froze it: the story of mSSH

How mSSH, a free SSH and SFTP client for iPhone, iPad and Mac, was built with Claude Code. The Thai keyboard bug, the iCloud crash, prompts, and the App Store link.

mSSH is an SSH and SFTP app for iPhone, iPad and Mac. I had Claude Code write it and put it on the App Store as a free app with no ads and no tracking. The source code is open on GitHub.

One day to an app that connects

According to Git, 30 March is where it began. At 8:44 pm it was an empty shell using the SwiftTerm library for the terminal screen and Citadel for SSH. Before 11 pm the main features were in: SFTP, host key checking with TOFU (trust the server's key the first time, warn me if it changes), iCloud sync, Face ID lock and SSH key import. That same night it was running on my iPhone. On the 31st I added the icon and fixed keyboard and connection problems.

I did not write that code. Claude Code wrote all of it, and it signed 34 of the 35 commits with Co-Authored-By. My time went into trying it on real devices.

A bug I only found because I type Thai

The bug report for version 1.0.1 is dated 2 April and covers two bugs. The first is one that someone who never types Thai would likely never meet. Switch to the Thai keyboard, type a character or two, and the terminal froze. Claude's finding: every keypress was sent to the SSH channel as its own separate write, but that channel was not built for several writes at once. A Thai character is three bytes, and the iOS Thai input method fires events faster than English does, so the writes collided. The fix was a queue so every write goes through one path, one at a time.

The second bug was a white screen after force-closing the app, which happened often after the first bug froze it. It taught me to test with the language I really use, not only English.

On the store, then Mac and split panes

5 April was version 1.1.0: a split terminal like iTerm2, a native Mac app, and the most interesting one, a button to launch Claude Code in a split pane. That means I can tell an AI to work on a server from my phone. Builds 3, 4 and 5 went to App Store Connect over two days, and build 4 was a fix for the export compliance answers (the encryption question).

iCloud sync crashed the app

I wanted connection data to sync between devices. At first I turned on CloudKit and the app crashed on a real device. It took two fixes on 6 April (removing a unique constraint from the data model, then switching sync off for the moment). By mid-month I aimed to get close to Termius and redid sync from scratch, including an option to sync private keys through end-to-end encrypted iCloud Keychain. It is a per-key choice, not on by default.

On the Mac there was still a layout crash, so I turned CloudKit off on macOS and used a simpler sync instead. My takeaway: if you let an AI move fast, it may start with a complicated approach, and you back out to a simpler one when real devices show the problem.

The tip jar, and the version number I could not reuse

In mid-April I added a tip jar: coffee $0.99, lunch $4.99, dinner $9.99, nothing locked behind it. When I went to send 1.2.0 again, that version was already closed to new builds, so I shipped it as 1.2.1 and then 1.2.2.

Made with AI. Claude Code wrote the code. I set direction, tested on my own phone and Mac, decided the scope, and submitted to the App Store.

Prompts (rewritten from the real features)

I could not find the first chat, so the text below is what I would type if I started today, built from the features in the real app and what I learned along the way. If you reuse it, change the feature list to match what you need.

1. Build the base app

Build an SSH and SFTP client for iPhone, iPad and Mac in Swift and SwiftUI (iOS 18+, macOS 15+).
- Terminal: use SwiftTerm for xterm-256color emulation; use Citadel for SSH.
- Connections: save hosts with groups, favorites and color tags; quick connect bar that accepts user@host:port.
- Auth: password, and OpenSSH keys (Ed25519, ECDSA, RSA). Generate Ed25519 keys inside the app. Keep secrets in the Keychain only.
- Host key: trust on first use (TOFU), show the SHA-256 fingerprint, warn loudly if it changes.
- SFTP: browse, upload, download, delete.
- Lock the app behind Face ID / Touch ID if the user turns it on.
Constraints: no analytics, no ads, no third-party tracking. Everything stays on the device unless the user turns on sync.
Ask me before choosing a library that is not in the list above.

2. Things to ask for right away

Test typing with the Thai keyboard (and any other IME). Characters can arrive in rapid bursts. Make sure every write to the SSH channel goes through one serial queue, never from concurrent tasks.
Also make sure the app never crashes at launch if the local database cannot open: show a recovery screen instead of a blank screen.

3. Sync across devices

Add optional iCloud sync for connections, snippets and key metadata across iPhone, iPad and Mac.
Private keys must sync only if the user turns it on for that specific key, and only through end-to-end encrypted iCloud Keychain.
If CloudKit causes crashes on a platform, fall back to key-value sync and tell me what you changed.

4. Ship it

Prepare the app for the App Store: privacy policy page, screenshots, release notes and the export compliance answers. Add an optional tip jar with three consumable tips and make sure nothing is locked behind payment. Do not reuse a version number that has already been uploaded.
A word of caution Never paste a password or a private key into a chat with an AI. If you need it to test a connection, use a throwaway server with a one-time key, and delete both afterwards.
