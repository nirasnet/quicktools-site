I told an AI to build me a GoodNotes-style app, and the transcript kept losing words: the story of mnotes

How mnotes, an iPad and iPhone lecture notes app with recording, transcript and summary, was built with Claude Code. The real prompts, the bugs and the App Store steps.

By 9M4ck · Beginner

  • From one sentence to a working iPad app
  • Three real bugs: a transcript that kept 10 seconds, a logo covering a button, and sync that did not sync

This one started with a single sentence I typed into Claude Code: I wanted an iPad note-taking app like GoodNotes, one that can take a photo of a slide, record audio, turn it into a transcript, summarize it and share it. I named it mnotes, short for Minimal notes. I didn't write a line of code myself.

Why I wanted it isn't written anywhere in the chat. My first prompt only says "lecture" and "GoodNotes". So I'm only telling you what the record shows: what I typed, what broke, and what got fixed.

The mnotes website

About the App Store link I searched the App Store for mnotes and couldn't find a public page for it yet, so there's no download link here. I'll add one when it's live.

The first prompt: everything in one sentence

On 30 September I typed one long message in my own kind of English. In the same sentence I asked for "awesome ux, ui", a logo, and "ready to deploy to app store". No spec, no wireframes. A couple of days later I told it to deploy to my iPad, and I could try the app for real.

The nice part is that I never needed to know what PencilKit or SwiftData are. I only knew I wanted to write with an Apple Pencil. If I ever want the names of the technologies, the README Claude wrote has them.

Two weeks later: "make it better"

I came back to the project on 14 October and asked for more useful features and nicer UX, and to install on both the iPhone and the iPad. After that it was the usual loop: try it, hit a problem, ask for a fix. Three stories stand out in the chat.

1. The transcript kept only the last 10 seconds

I recorded about 27 seconds and the transcript showed only the last 10. I typed "is bug please check and fix it". The next day on the iPad it happened again, and tapping "re-transcribe" erased the text I already had. I reported it three times over two days.

According to the notes Claude kept, the cause was that Thai speech recognition sends partial results and starts counting again after a pause, so earlier text was being overwritten. The fix was to keep finished sentences, keep about 65 seconds of audio so it can be replayed into a new request, and, if live transcription fails, keep recording and transcribe from the file afterwards. I didn't find the cause myself. I only knew it was wrong because I tried it.

2. The "m" logo covered the New note button

I asked it to redo the home screen with a hero section like the best note apps. Claude built a big welcome card. On the real iPad the "m" logo was so large that it covered the New note and Scan slides buttons. I wrote "hero card logo m is cover button", and it reworked the layout so the buttons wrap on narrow widths and the logo hides when there isn't room.

3. iCloud sync that didn't sync

I asked for saving to the cloud and syncing with other devices in the same ecosystem, like an iPhone and an iPad. Once on, the app said it was syncing, but the two devices didn't match. I asked "why it not sync, fix it", then how often it syncs, whether I could pull manually, and whether it could show progress per item.

Claude changed the data models to work with CloudKit, moved photos and audio into a form that can sync, and added a Sync now button and a recent-activity list in Settings. For testing I plugged the iPad in over USB so it could read the logs from the real device, and it confirmed that both devices imported and exported within seconds. Sync runs on push notifications and when the app opens. It doesn't poll every minute.

Publishing to the App Store, with the AI doing the whole process

On the night of 15 October I typed "upload it to app store which story and all image for me automate 100%". I wanted the story, the screenshots and all the listing details filled in. Claude wrote scripts that build the app's website, set up the listing in App Store Connect and upload the screenshots. I only stepped in where Apple's website needed my own click.

It wasn't smooth. The script failed to set the age rating and got a 409 error several times, so I ran it again until it passed. Then the app icon was missing from the listing ("why it not have app icon on appstore connect"), and later the Header and Search Results artwork was empty, so I asked it to make that too. In the end I asked Claude to write the whole publishing procedure down as a skill I can reuse for other apps.

What came after

The project only has 6 commits, because it wasn't under git until I uploaded it to GitHub on 20 October. But the later work is visible. On 21 October it fixed ink being saved to the wrong page and janky page adds. Then it added a tip jar with three consumable purchases named coffee, lunch and dinner, bumped the version to 1.3.0, with scripts to attach the build and submit the tip items to Apple.

What this app taught me The bug I reported three times (lost transcript) was the kind that only shows up on a real device with real speech, not in the simulator. If you build an app like this with AI, keep a real device nearby and tell the AI what you saw, not just that it's wrong.
